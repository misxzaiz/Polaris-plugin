# zcode-bridge「好用版」插件设计（v1 目标形态）

> 定位：让 ZCode 桌面版的会话能力，在 Polaris 面板里像「第一方功能」一样顺手。
> 收敛自 PLAN-next-phase.md：工作区 / 模型 / 权限三条线，统一收进一个以易用性为中心的产品。
> 本设计只描述目标形态与交互，实施阶段单独拆。

---

## 0. 设计原则（易用性优先）

1. **默认零配置**：打开面板就能列会话、能对话。所有高级项（工作区/模型/权限）有合理默认，不强制先设置。
2. **一处入口全做完**：会话列表 → 点开即聊 → 顶部可换工作区/模型，不跳出面板。
3. **状态可见**：当前工作区、当前模型、连接状态、流式进度，都常驻可见但不打扰。
4. **失败可恢复**：模型超时/断连/权限不足，给清晰文案 + 一键重试，而不是卡死。
5. **跨端一致**：桌面和移动端同一个面板，同一个数据流（已是 cap.http 转发，保持）。

## 1. 面板信息架构（三屏一栏）

```
┌─────────────────────────────────────────┐
│ [工作区 ▾]   ZCode 会话     [+ 新对话]  │  ← 顶栏：工作区选择全局常驻
├─────────────────────────────────────────┤
│  ◎ 会话卡片（标题 / 时间 / 目录）        │  ← 列表屏：最近会话
│  ◎ 会话卡片（标题 / 时间 / 目录）        │
│    搜索框 🔍 过滤                          │
├─────────────────────────────────────────┤
│ [← 列表]  {会话标题}       [刷新]        │  ← 聊天屏：对话
│   顶栏第二行: [工作区 chip] [模型 chip]  │
│   消息流（流式渲染）                      │
│   [输入框.................] [发送]       │
└─────────────────────────────────────────┘
```

- **一个全局工作区选择**（列表屏 + 聊天屏顶栏同一处）——切换即刷新会话列表。
- **聊天屏模型 chip**：可点 → 弹模型选择（若可切换）或提示「当前由 ZCode 桌面版决定」。

## 2. 核心体验设计

### 2.1 工作区（易用优先的 P0）
- **默认**：`上次使用的工作区`（插件本地记忆，localStorage 持久化），首次为「全部工作区」或 ZCode 最近会话目录。
- **下拉选项**：
  1. 「全部工作区」（默认，显示所有会话）
  2. 各会话 directory 去重列表（ZCode 已落库的）
  3. 手动输入任意路径（+）
- **新对话**：落到当前选中工作区；未选时落到「最近会话的目录」。
- **显示**：会话卡片始终显示其 directory（小字），即使用户不选也能感知归属。

### 2.2 模型（克制实现）
- **展示**（必做）：聊天屏顶栏 chip 显示当前 ZCode 实际用的 provider/model（从会话元数据或 usage 解析）。
- **切换**（尽力而为）：点 chip → 若 `session/send` 实测支持 `model` 覆盖则列出可选模型；不支持则显示「模型由 ZCode 桌面版决定，可在 ZCode 里切换」+ 一键打开 ZCode。
- **不做的**：不试图把 Polaris 自己的 provider 塞进 ZCode（那属于路线 Y，独立立项）。

### 2.3 权限（分级 + 渐进提示，不吓人）
| 档位 | 能力 | 默认 | 触发方式 |
|---|---|---|---|
| L1 | 会话只读 + 对话 | ✅ 默认 | 无 |
| L2 | 可写当前工作区（ZCode 改文件） | 关闭 | 会话卡片「允许 ZCode 修改此工作区」开关，首次操作时面板提示 |
| L3 | 网络 + shell | 关闭 | 需要时面板弹「此操作将授予 ZCode 完全访问」二次确认 |

> 权限的真实载体仍是 Polaris config rule；面板只是「请求」+ 显示状态，不在插件侧自封权限。

## 3. 数据流与状态（保持现状架构，仅补缺口）

```
面板(三屏) ──cap.http──▶ server.js(9862) ──stdio──▶ ZCode app-server
                              │
                              ├─ /api/sessions        （已有）
                              ├─ /api/workspaces      （新增：读 db.directory DISTINCT）
                              ├─ /api/session/:id/msgs（已有）
                              ├─ /api/chat/create     （已有，补 workspacePath 参数）
                              ├─ /api/chat/resume     （已有）
                              ├─ /api/chat/send       （已有，补 workspacePath/model 参数）
                              └─ /api/chat/events     （已有，await 已修）
```

**状态可见性**（面板顶部常驻一行小状态）：
- `ZCode ● 已连接` / `○ 未连接`（server.js /__health 心跳）
- `工作区：D:/space/base/Polaris`
- `模型：deepseek-v4-flash`
- 连接断开时：列表屏顶部红条 + 「重试」按钮；不白屏。

## 4. 易用性细节清单

| 痛点 | 方案 |
|---|---|
| 新用户不知道工作区是什么 | 首次打开弹一行引导：「选择一个工作区，或直接开始对话（用最近目录）」 |
| 会话多了找不到 | 列表屏顶部搜索框（按标题/目录模糊过滤，前端本地过滤即可，不上后端） |
| 发完消息没反应 | 输入区下方显示「正在等待模型…」+ 超时（60s）后给「重试 / 取消」 |
| 流式中途失败 | 保留已收到的文本，显示「回复被中断」+ 重试按钮（续接而非重发） |
| 想不起这个会话在哪个目录 | 卡片永远显示 directory 小字 |
| 桌面版能看到的会话面板看不到 | 「全部工作区」兜底 + 刷新按钮 + 顶部提示当前列表范围 |
| 中文/编码疑虑 | 已用 node 客户端验证 UTF-8 全链路正常（curl 假乱码不属产品问题） |

## 5. 实施拆解（可排期）

| 阶段 | 内容 | 验收 |
|---|---|---|
| S1 | 工作区：server 加 `/api/workspaces`；panel 顶栏下拉 + 记忆；create/resume 传 workspacePath | 面板可选工作区，新会话落对目录，切换刷新列表 |
| S2 | 模型 chip：解析当前 model 展示；实测 send 带 model；决定「可切 or 仅展示」 | 聊天屏可见当前模型；切换结论已定 |
| S3 | 权限分级：panel 请求 → config rule 联动；L2/L3 渐进提示 + 二次确认 | 用户可自选档位，权限状态可见 |
| S4 | 体验打磨：状态行 / 搜索 / 超时重试 / 中断续接 / 错误文案 | 断连、超时、失败都有明确反馈和恢复路径 |

---

## 6. 不做清单（避免过度设计）

- ❌ 不接 Polaris 自有 provider 进 ZCode 会话（路线 Y，另立）。
- ❌ 不做多会话并列编辑、不做代码差异展示（超出「遥控 ZCode」范围）。
- ❌ 不在插件内实现自己的权限系统——权限一律走 Polaris PolicyPermission，插件只请求与展示。
- ❌ 不做「完全访问 = 一刀切全开」；只有分级 L2/L3，且 L3 显式确认。
