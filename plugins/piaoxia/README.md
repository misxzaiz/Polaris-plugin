# 发票保险库（piaoxia）—— 个人电子发票保险库

> 把散落在下载文件夹 / 微信卡包导出 / 邮箱附件里的**电子发票文件**，收拢成一本可对话、可判重、可跟踪报销状态、可支撑保修维权的本地票账。

## 解决什么问题

- **发票散落**：数电票时代发票以 PDF/XML 文件形态散落在各处，报销时翻箱倒柜。
- **重复报销**：同一张票分两次提交被财务打回——发票保险库用 20 位发票号码全局判重，收票即拦。
- **报销失忆**：「上个月交通费报了多少」「哪些票还没报」一句可查；开票超 60 天未报销主动点名。
- **保修无据**：电子发票就是购买凭证；登记保修月数即得到期倒计时，维权时原件归档随查随有。
- **抬头手抄**：公司/个人开票信息一键复制。

## 使用方式

**AI 对话**（MCP 通道，7 个工具）：

- 「把下载文件夹里的发票收进来」→ `piaoxia_collect`（扫描目录，解析 PDF 文本层/数电票 XML，归档原件，逐票判重）
- 「记一张出租车票 45 块」→ `piaoxia_add`（手录/对话录入，纸质票走这里）
- 「哪些票还没报」「这个月能报多少」→ `piaoxia_query type=pending/stats`
- 「这批发上去了，单号 R202611-1」「到账了」「被财务打回了」→ `piaoxia_set_status`
- 「这台空调保修三年」「那张票算招待」→ `piaoxia_update`
- 「记一下我们公司开票信息」→ `piaoxia_titles`
- 删除需 `confirm=true` 且 AI 先向你确认。

**面板**（四个 Tab）：

- **收票台**：拖拽 PDF/XML + 目录扫描，三色结果（新增/重复/失败原因），解析警告逐票列明。
- **票册**：过滤（状态/分类/月份/关键词）+ 详情（状态流转按钮按状态机动态出现、报销单号、保修期、归档路径）+ 手动录入 + 两击删除。
- **透视**：待报销/在途/本月/年度四卡 + 近 12 个月节奏 + 分类构成 + 报销单分组 + 保修到期榜 + 销方 TOP10 + CSV/JSON 导出。
- **抬头与设置**：抬头 CRUD（默认抬头/一键复制）、JSON 备份恢复、CSV 迁移导入、服务状态探测、口径与边界说明。

## 数据与安全

- **纯本地**：票据数据存宿主 `cap.kv`（键空间 `piaoxia.invoice.*` / `piaoxia.title.*` / `piaoxia.meta`）；原件复制归档到 `<数据根>/piaoxia/<发票号码>.pdf`（永不覆盖，重名 -2/-3）；**零外网请求**。
- **解析服务**：只绑 `127.0.0.1` + token（token 经 cap.kv meta 分发给面板）；输入文件只读不改；PDF 走文本层抽取（pdfjs），数电票 XML 结构化解析（UTF-8/GBK 自适应）。
- **判重三层**：文件 sha256 相同 → 同文件；发票号码相同 → 同票（原件可补挂到已有票，账面不动）；手录无号码按「日期+销方+金额+品名」内容寻址幂等。
- **写入唯一入口**：面板、AI、服务三方共用 `shared/core.js` 的 normalize/状态机/派生，口径不漂移；id 内容寻址，并发写同票覆盖不分裂。

## 明确不做（边界）

- **不做 OCR**：扫描件/图片型 PDF 无文字层，如实报错并引导手动录入。
- **不做 OFD**：数电票 OFD 版式（zip 容器）暂不支持，请从电子税务局下载 PDF 或 XML。
- **不做发票查验**：不对接税务查验接口；真伪请走官方平台。
- **不做企业审批流**：个人票据账。

## 测试

```bash
node test/run-tests.mjs      # core 纯函数 80 断言（状态机全转移/判重三层/透视口径/CSV 往返）
node test/parse-verify.mjs   # 解析引擎 60 断言（仿真 CID 字体 PDF fixture + 三风格 XML + GBK）
node test/mcp-verify.mjs     # MCP 全流程 32 断言（内存桥 + spawn）
node test/service-verify.mjs # 服务 HTTP 18 断言（鉴权/扫描/归档/meta）
node test/smoke-real.mjs     # 真宿主冒烟 7 断言（需 Polaris 运行中，快照式清理）
```

fixture 由 `test/make-fixtures.mjs` 生成：手写最小 PDF 写入器（Type0 CID 字体 + Identity-H + ToUnicode CMap + FlateDecode，内嵌本机中文字体），复刻真实电子发票 PDF 的字型路径——不是 pdf-lib 标准字体的假捷径。

## 架构

```
面板(React) ──拖拽字节──> service(HTTP 127.0.0.1+token) ──engine──> 解析+归档
    │                            │
    └── cap.kv 写入 <────────────┘（服务只解析不写账）
AI 对话 ──> mcp/server.js(stdio) ──engine+vault──> 解析+归档+cap.kv 写入
三方共用 shared/core.js（normalize/状态机/buildView/CSV）与 service/engine.js（解析）
```

已知限制：解析成功率依赖票面文字层质量，异常票面会给出 ⚠ 警告清单；跨版式（地方特色票样）如遇字段错位请手动修正，发票保险库不静默吞错。
