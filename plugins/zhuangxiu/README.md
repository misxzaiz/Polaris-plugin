# 装修台账 zhuangxiu —— 家庭装修对账本

> 把「装修公司的报价单、记不全的每笔开销、总在涨的增项、说不清的工期节点」变成**可对话、会对比预算、能盯住增项**的装修账。
> 聊天里说「瓷砖买了 3200，张师傅装的」一句话入账；超支标红、临超标黄；报价单外科目一步建「增项科目」并单独合计。
> 对账结果用于家庭自查，**不构成造价咨询或法律建议**。

## 为什么要有装修台账

- **装修超支是普遍痛**：新华网报道低价签约后增项致预算超支 30%+；千库网有 13368 个装修记账 Excel 模板——PC 侧无好工具，手工 Excel 是主流且难坚持。
- **增项是装修公司的主要利润手段**：报价单故意漏项（垃圾清运/包立管/防水/过门石/美缝……），后期以「合同里没包含」加钱。破解方法论（豆瓣装修账簿帖）：**逐项报价预算表 + 每笔当天入账 + 与报价比对盯增项**——正是本插件的三个核心能力。
- 现有方案缺口：专用 App 手机端为主且小众；通用记账无「科目预算对比 / 增项口径 / 供应商档案 / 工期节点」维度；Excel 手动汇总易错难坚持。
- 装修涉及价格敏感信息：**纯本地存储**（cap.kv，不出设备），无账号、无上传、零外网请求、零服务进程。

## 核心能力

| 能力 | 说明 |
|---|---|
| 标准科目模板 | 30 项预置科目（10 分组），**内嵌防漏项清单**——垃圾清运/包立管/防水/过门石/美缝/物业押金管理费/开荒保洁，一键采用 |
| 预算 vs 实际 | 每科目预算/已花/进度条，**超支红 / ≥90% 黄 / 未定灰 / 正常绿**；总预算优先于科目合计 |
| 增项口径 | 科目 `isExtra=true` ⇒ 支出计入增项合计；`asExtra:true` 一步建增项科目并记账；asExtra 模糊命中已有科目时拒绝（不静默改记普通科目） |
| 对话式记账 | 「瓷砖买了 3200，张师傅装的」→ 自动归科目 + 供应商自动建档 + 返回该科目预算执行快照 |
| 幂等防双写 | 传 `id` 覆盖同 id 记录；覆盖时**未提供的字段继承旧值**（重试丢字段不抹数据） |
| 供应商档案 | 角色/电话/合同额 + 已付统计（谁干了啥、付了多少） |
| 工期节点 | 红黄榜：逾期红 / 3 天内黄 / 完成绿（记录与提示，不推送） |
| 常见漏项检查 | 预算单缺防漏项清单科目时，总览与小结都会提醒（漏报=后期增项） |
| 对账小结 | 一键 markdown：总执行/分科目表/超支榜/漏项提醒/供应商付款/节点——可直接发家人 |
| 多端同录 | 手机浏览器打开同一面板记账；面板+AI 共读同一份 cap.kv 事实库 |

## 快速开始

1. 插件中心安装「装修台账」→ 左侧 ActivityBar 出现 📋 面板（零后台服务，打开即用）。
2. 「科目」页点**一键采用标准科目模板**（或直接对 AI 说「用装修台账给我建标准科目」），再按报价单逐科目录预算（`zx_category action=set` 或面板点科目改预算）。
3. 之后每笔开销对 AI 说，或面板「流水」页手工记：

```
瓷砖买了 3200，张师傅装的，微信付的
记一笔增项：窗台大理石加固 600
```

4. 随时问「装修花了多少了/哪个科目超支了/增项一共多少钱」，或「生成对账小结」发给家人。

## 与 AI 的对话约定（MCP 工具）

| 工具 | 用途 |
|---|---|
| `zx_record` | 记一笔支出（科目按名解析；报价单外科目拒单并引导 asExtra；vendor 按名自动建档；`id` 幂等覆盖） |
| `zx_category` | 科目 add / set（录预算）/ remove（有支出拒删）/ list / **template**（一键标准科目）/ project（项目档案与总预算） |
| `zx_query` | 查询（只查不建）：`budget` 预算执行 / `recent` 流水 / `extra` 增项 / `vendors` 供应商 / `milestones` 节点红黄榜 / `missing` 常见漏项 |
| `zx_vendor` | 供应商 add / set / list |
| `zx_milestone` | 工期节点 add / set / done / list |
| `zx_update` | 按 id 改支出（金额/科目迁移/日期/供应商/备注） |
| `zx_delete` | 删支出/科目/供应商/节点（`confirm:true` 门） |
| `zx_summary` | 对账小结 markdown（只查不建） |

**口径纪律**：增项口径唯一 = 科目 `isExtra:true`；标色唯一 = `spent>budget` 红 / `≥90%` 黄 / 未定灰；节点唯一 = 逾期红 / 3 天内黄。全部在 `shared/core.js` 单一权威实现，面板与 MCP 结论永远一致。

## 架构

```
┌────────────── 面板（总览/科目/流水/档案）────────────────┐
│  __POLARIS_HOST_INVOKE__ → router_dispatch → cap.kv     │
│  零外网、零服务进程；预算对比/增项/漏项/小结全部 core 现算  │
└──────────────────────────┬──────────────────────────────┘
                           │ 读写 zhuangxiu.* 键空间
┌──────────────────────────┴──────────────────────────────┐
│ shared/core.js 纯函数核心（双方同源，同一口径）             │
│  normalize×5 · resolveCatName · budgetCompare            │
│  missingCheck · milestoneLevel · buildSummary · TEMPLATE │
├──────────────────────────────────────────────────────────┤
│ mcp/server.js（stdio JSON-RPC；零依赖）                   │
│  AI 工具层：翻译 tools/call → cap.kv zhuangxiu.* 读写      │
│  （经 kvclient 自发现桥端点；查/小结只查不建）              │
└──────────────────────────────────────────────────────────┘
```

**为什么零服务进程**：核心是「记录 → 对比 → 提示 → 小结」，全部可在读取时现算（单项目量级：科目 ~30 / 支出数百，远低于任何分块阈值）。提醒类需求由面板红黄榜 + AI 查询承担，不建常驻服务、不多一个故障面。

**键空间契约**（双方一致）：

| 键 | 写者 | 读者 | 说明 |
|---|---|---|---|
| `zhuangxiu.project` | 面板/MCP | 面板/MCP | 单项目档案（v1 单项目）`{id,name,house?,totalBudget?,status,startDate?}` |
| `zhuangxiu.cat.<id>` | 面板/MCP | 面板/MCP | 科目 `{id,name,group,budget?,isExtra,order,…}` |
| `zhuangxiu.exp.<id>` | 面板/MCP | 面板/MCP | 支出 `{id,catId,amount,ts,vendorId?,payMethod?,note?,src,…}` |
| `zhuangxiu.ven.<id>` | 面板/MCP | 面板/MCP | 供应商 `{id,name,role?,phone?,contractAmount?,note?,…}` |
| `zhuangxiu.mile.<id>` | 面板/MCP | 面板/MCP | 节点 `{id,title,date,done,note?,…}` |

每记录一键：写入为单命令原子操作，无数组读改写、无跨日迁移；删除供应商保留历史流水（仅解除关联）。

## 已知边界

- v1 **单项目**（多项目/多套房留待后续）；不做报价单 OCR/文件导入、账单分摊、支付对接。
- 节点只做红黄榜记录与提示，**不做主动推送**（可用「日程提醒」插件对节点日期设提醒）。
- 无地图/材料价格行情等外部数据；对账结果用于家庭自查，不构成造价咨询或法律建议。
- 供应商删除为「解除关联」语义（历史流水保留），防误删账。
