# 脉案 maian —— 家庭体征台账

> 把「爸妈的血压本、血糖记录、每次量的体温体重」变成**可对话、会标色、能带走**（就诊小结）的家庭健康资产。
> 脉案者，医者所记之医案也——家人自测的每一个数字都值得被留下、被看见、被带去复诊。
> 只做记录与呈现，**不提供医疗建议**；分带为通用参考区间，请遵医嘱。

## 为什么要有脉案

- 医疗流程**强制「记录」环节**：《中国高血压健康管理规范》建议初诊/调药期连续自测家庭血压 7 天、平稳期每周 1-2 天，测量后记录成册、**复诊时提供给医生**——医院至今在发纸质血压记录本（手写、易丢、难分析）。
- 现有血压记录 App 的用户抱怨集中在：弹窗广告、会员墙、强制注册、老人不会用；且全部是「单人单设备」维度——**家庭维度**（子女替父母记、全家一册、桌面+手机同录）无主流产品（与青囊立项时同一论证）。
- 健康数据极敏感：脉案**纯本地存储**（cap.kv，不出设备），无账号、无上传、零外网请求、零服务进程。

## 核心能力

| 能力 | 说明 |
|---|---|
| 家庭成员档案 | 全家一册；身高可选（用于 BMI 分带），备注随访背景 |
| 四类指标 | 血压（收缩/舒张/心率）、血糖（空腹/餐后2h/随机/睡前四时点）、体温、体重 |
| 通用参考分带 | 血压五态（绿 <130/85 · 黄 130-139/85-89 或偏低 · 红 ≥140/90 · 急 ≥180/120）、血糖按时点、体温、体重按中国成人 BMI；全部标注「请遵医嘱」 |
| 对话式记录 | 「妈早上血压 152/95 心率 78」一句话入账；成员不存在按名自动建档；返回分带 + **较上次变化**（如「收缩压 -14」） |
| 幂等防双写 | 传 `id` 覆盖同 id 记录——AI 重试不会双写 |
| 趋势与统计 | 近 7/30 天（区间自选）均值/最高/最低/分带计数 + 手搓 SVG 折线（血压双系列，点色=分带） |
| 就诊小结 | 成员+时间段 → 结构化 markdown（统计+分带+逐条明细表+免责），复制即可带给医生 |
| 改错成本低 | 按 id 修改（值/时间/备注/成员），跨日/跨月自动迁移日键；删除有 confirm 门 |
| 多端同录 | 手机浏览器打开同一面板替家人记录；面板+AI 共读同一份 cap.kv 事实库 |
| 数据所有权 | 设置页一键全量导出 JSON |

## 快速开始

1. 插件中心安装「脉案」→ 左侧 ActivityBar 出现 💓 面板（零后台服务，打开即用）。
2. 「设置」页建家庭成员（如「妈妈」，可填身高）——或者什么都不填，直接对 AI 说：

```
帮我记一下：妈妈早上血压 152/95，心率 78，服药前测的。
```

3. 复诊前对 AI 说「生成妈妈这个月的就诊小结」，复制结果带给医生。
4. 测量提醒交给「日晷」日程插件（如「每天早上 8 点提醒我妈量血压」）——脉案专注记录与分析，不重复造提醒。

## 与 AI 的对话约定（MCP 工具）

| 工具 | 用途 |
|---|---|
| `maian_log` | 记一笔（血压/血糖/体重/体温；按名自动配档；`id` 幂等覆盖；返回分带+较上次变化） |
| `maian_query` | 查询：`recent` 近期记录 / `stats` 区间统计（需成员）/ `flags` 黄红榜（需成员）/ `members` 成员一览 |
| `maian_member` | 成员建档/列表/改档案（身高启用 BMI 分带） |
| `maian_update` | 按 id 修改一笔（跨日自动迁移日键） |
| `maian_delete` | 删除一笔（`confirm:true` 门） |
| `maian_summary` | 就诊小结（成员+时间段 → markdown；只查不建，打错名字不会长出垃圾成员） |

**分带是通用参考区间，不是诊断**——工具描述与输出明确不推断病情、不推荐用药；查询/小结视图只查不建档，只有记录动作才会自动建档。

## 架构

```
┌─────────────── 面板（记录/趋势/台账/设置）────────────────┐
│  __POLARIS_HOST_INVOKE__ → router_dispatch → cap.kv      │
│  零外网、零服务进程；分带/统计/小结全部 core 现算           │
└──────────────────────────┬───────────────────────────────┘
                           │ 读写 maian.* 键空间
┌──────────────────────────┴───────────────────────────────┐
│ shared/core.js 纯函数核心（双方同源，同一口径）              │
│  normalize×2 · bandOf 分带 · statsFor · trendPoints      │
│  buildSummary 小结 · upsert/remove 日键操作               │
├──────────────────────────────────────────────────────────┤
│ mcp/server.js（stdio JSON-RPC；零依赖）                   │
│  AI 工具层：翻译 tools/call → cap.kv maian.* 读写          │
│  （经 kvclient 自发现桥端点；零外网；查/小结只查不建）        │
└──────────────────────────────────────────────────────────┘
```

**为什么零服务进程**：青囊需要常驻服务算「应服投影」并主动提醒；脉案的核心是记录→分带→统计→小结，全部可在读取时现算（家庭量级：千人级记录/年，远低于分块阈值）。提醒类需求复用日晷，不重复建服务、不多一个故障面。

**键空间契约**（双方一致）：

| 键 | 写者 | 读者 | 说明 |
|---|---|---|---|
| `maian.member.<id>` | 面板/MCP | 面板/MCP | 成员档案 `{id,name,heightCm?,note,createdAt,updatedAt}` |
| `maian.day.YYYY-MM-DD` | 面板/MCP | 面板/MCP | 该日全部记录数组（按 ts 升序，同 id 覆盖）|

记录形状：`{id, profileId, kind: 'bp'\|'bg'\|'weight'\|'temp', ts, sys?, dia?, pulse?, mmol?, slot?, kg?, c?, note, src: 'panel'\|'ai', at}`。

**口径纪律**：记录唯一写入口径 = `core.normalizeRecord`（校验范围/时间/裁剪）；分带唯一口径 = `core.bandOf`（血压家庭自测口径、血糖指尖时点口径、体温、中国成人 BMI 18.5/24/28）；面板与 MCP 不各自实现，结论永远一致。

## 已知边界

- 只做记录/呈现/小结，**不做任何医疗推断**；分带阈值内置、暂不支持自定义个性化目标（医生给的个体目标请写进备注）。
- 血糖为指尖血 mmol/L 口径（不做 mg/dL 换算）；连续血糖仪/血压计蓝牙对接、检验报告 OCR 不在 v1。
- 提醒不做（复用日晷）；面板打开时才轮询（5s 键集 diff + 90s 全量兜底），不做推送。
- 导出/小结为文本形态（复制/textarea），不做 PDF 排版（纸坊可承担排版需求）。
