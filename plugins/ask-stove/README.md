# 食材管家（ask-stove）

把「冰箱里有啥、今晚吃啥、周末买啥」变成可对话的资产。

## 能做什么

- **库存**：食材五分区（冷藏/冷冻/干燥/调味/其他）+ 到期日；临期红榜（过期红、临期黄），一键记「吃掉了/扔掉了」。
- **灶签**：每天推荐「今天吃什么」，完全可解释——临期食材加分、缺料降权、近 7 天做过的回避，每条带理由，一键「就吃这个」排进今日。
- **菜谱**：手动添加；或贴 URL 一键导入（后台服务原生 fetch，绕开浏览器跨域；SSRF 守卫只放行公网 http/https）；抓回的正文可「填入表单」或「发给 AI 提取」。
- **本周计划**：7 天排菜或写备注（外卖/剩菜）。
- **采购**：「按计划补齐」把未来 7 天计划菜谱的缺料（扣掉在库）自动进清单，按超市动线六类分组，手机上边逛边勾。
- **浪费透视**：吃掉 vs 扔掉、浪费率、最常扔的食材、12 周趋势——让「下次少买点」有数据支撑。

## 对 AI 说什么

插件带 12 个 `stove_*` MCP 工具，直接在聊天里：

- 「买了两斤排骨一把小葱，周末前吃完」→ AI 解析后调 `stove_pantry_add` 入库（到期日自动算）
- 「番茄用掉了」→ `stove_pantry_consume`（同义匹配：西红柿=番茄）
- 「今晚 20 分钟能做啥」→ `stove_suggest` 带理由推荐
- 「帮我把这个菜谱存下来：<URL>」→ `stove_recipe_import` 服务端抓取 → AI 抽取 → `stove_recipe_save`
- 「按这周计划补一下购物清单」→ `stove_shopping fill_from_plan`
- 「我这周扔了多少东西」→ `stove_stats`

## 同名不打架

内置 31 组同义词（番茄=西红柿、土豆=马铃薯、生抽=酱油…），全角/大小写/括注/空白统一归一——「冰箱有西红柿、菜谱写番茄」能对上；消耗、缺料、采购去重全走同一套匹配。

## 数据与安全

- 数据全部在 Polaris 数据根（cap.kv，`stove.*` 键），桌面/手机同源；面板可导出 JSON、一键清空。
- 插件唯一外联点是后台服务的菜谱抓取：仅公网 http/https（拒绝环回/内网/链路本地/云元数据端口）、8s 超时、2MB 体量上限、正文截断 8KB。
- 面板零直连外网：数据走宿主 `router_dispatch`，抓取走命令邮箱（`stove.cmd.fetch.*` → 服务先删后做 → `stove.result.*`）。

## 开发

```
npm install          # 面板构建依赖（esbuild/tsc）
npm run build        # dist/panel.js
npm run typecheck    # tsc --noEmit
npm test             # 离线单测（core 纯函数 21 项）
node test/smoke-real.mjs   # 真机冒烟（需 Polaris 运行中；有真实数据时自动拒绝执行）
```

## 已知边界

- `stove.history` 为多写者追加（面板与 AI 都可能消耗食材），双端同一瞬间动作理论上可能丢一条统计事件；核心状态（库存/菜谱/计划/采购）为单对象原子换写，无此问题。
- 面板不做扣半份消耗（整份为主）；细粒度扣减走 AI（`stove_pantry_consume` 带 qty）。
- 灶签依赖菜谱库：没有菜谱时先加几道（手动或 URL 导入）。
