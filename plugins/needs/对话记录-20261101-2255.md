# 根因定位结论：dbx issue #13997

## 1. 根因（一句话）

收起连接后，`ConnectionTree.vue:2597` 的 `selectActiveTabSidebarNode` watcher（监听 `flatNodes`，flush:post）立即触发：因收起使当前 active tab 的行从 `flatNodes` 消失 → `findSidebarNodeForActiveTab` 返回 null → 回退到 `expandSidebarNodePath(nodePath)`（`ConnectionTree.vue:2556-2560`）**把刚收起的连接重新展开**。toggle 收起本身正确（`SidebarTreeRuntimeHost.vue:1095-1100` 对称同步 liveNode），缺陷在被动 auto-select 路径覆写了用户操作。

## 2. 支撑证据

**A — toggle 收起路径对称，非根因**
- `SidebarTreeRuntimeHost.vue:1095-1100`：`node.isExpanded=false` → `emitNodeToggled(node, wasExpanded, false)`。
- `emitNodeToggled`（`:8890-8905`）：`canTreeNodeExpand("connection")`=true（connection 不在 `sidebarTreeItemLayout.ts:3` 的 leafTypes），同步 `liveNode.isExpanded=false`。
- 展开分支 `:1155-1157`（12a9973 新增）+ try 结尾 `:1270 emitNodeToggled` 同样对称。单看 toggle 无不对称。

**B — activeNode 引用链正确**
- `activateRuntimeNode`（`:8883-8885`）设 `activeNode.value = node`；`emitNodeToggled:8892` 设 `activeNode.value = liveNode`。watch（`:520-527` flush:post）在 treeNodes 变更后重解析 liveNode。引用脱钩不成立。

**C — 双击 vs 单击序列**
- 双击模式：`TreeItem.vue:1519` 的 `onClick` 先判 `shouldActivateTreeNodeOnSingleClick(connection, "double")`=false → click(detail=1/2) 不进 handleRowClick；仅 dblclick → `handleRowDoubleClick` → `onDoubleClick:1788` → `treeNodeRowDoubleClickAction` 走 `:219 if (canExpand) return "toggle"` → toggle 展开。净 toggle 1 次。
- 单击模式：click(detail=1) action=toggle 即展开；click(detail=2) 被 `shouldRunTreeNodeRowAction(action, 2)`=false 拦；dblclick 单击模式 connection 走 `:202 open-database-browser`（非 toggle）。净 toggle 1 次。
- 两种模式净 toggle 相同 → 单/双击差异不是根因（与 #13895 评论一致：connection 一律收不起）。

**D — 被动 auto-select 路径（真根因）**
- `ConnectionTree.vue:2547-2566` `selectActiveTabSidebarNode`：`findSidebarNodeForActiveTab(tab, flatNodes)` 返回 null 时，`findNodePathForTarget` 取路径 → `expandSidebarNodePath(nodePath)`（`:1780-1781` 调 `expandSidebarLocatePath`，用 `store.canUseLoadedTreeNodeToggle` 放行）。
- `:2597-2610` watcher 监听 `[activeTab.id, flatNodes, autoSelectEnabled]`，flush:post。收起连接 → flatNodes 缩 → 触发 → 重新展开。
- connection 的 children 在 `loadedTreeNodeChildrenIds` 注册 → `canUseLoadedTreeNodeToggle(connection)`=true → 被动展开放行；database 通常未注册 → 展开不了 → 「database 能收起、connection 收不起」的不对称（#13895 评论明确指出）。
- 「重启自动展开后收不起」：重启恢复展开的 connection 同样在 loadedTreeNodeChildrenIds 注册，同一被动路径覆写。

**E — 测试缺口**
- `SidebarTreeRuntimeHost.expansion.spec.ts` 中 12a9973 新增的两个 `issue #13536` 测试只断言 `isExpanded` 变 true，未测「展开后再 toggle 收起」。且这是 RuntimeHost 单元测试，根本不覆盖 ConnectionTree 的被动 auto-select watcher —— 缺陷所在层无测试。

## 3. 单击 vs 双击 / 重启的差异机制

根因与单/双击无关。决定性条件是 **`autoSelectActiveSidebarNode` 偏好开启 + 当前 active tab 的行位于该 connection 子树内 + connection 子节点已注册在 loadedTreeNodeChildrenIds**。任一条件不满足就不复现：
- database 能收起：未注册 → 被动路径无法展开 database。
- 关闭 autoSelectActiveSidebarNode 偏好：watcher `:2551` 直接 return。
- 无 active tab 或 tab 行不在该 connection 下：findSidebarNodeForActiveTab 不触发回退。

#13997 报「双击打开」只是双击激活模式用户的典型入口；#13895（v0.6.61）报箭头收不起、#13839 折叠按钮失效、#13849 始终选择已打开项，四处同源。

## 4. 可直接写成 vitest 的复现断言

## 5. 修复方向（最小改动）

不要改 toggle / emitNodeToggled（它们正确）。改 `selectActiveTabSidebarNode` 的回退条件，与 wunaixaukong #13895 PR 一致：
- 被动展开仅在「active target 真正移动了」（tab 切换、或偏好刚开启）+ 「tab 行从未到达过」（session 恢复/元数据仍在加载，给一次重试）时触发；
- 同一 tab 已在树中显示后的普通 tree 更新，只选中行，不再 `expandSidebarNodePath` 重开用户刚关的连接；
- 用决策表单测覆盖：moved / same-tab-already-revealed / same-tab-never-revealed / preference-off。
