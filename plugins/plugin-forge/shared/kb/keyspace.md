# cap.kv 键空间纪律

cap.kv 是 SqliteStorage 的 kv domain，**所有插件共享一个键空间**：`list` 动作返回全部键（不分插件、无前缀过滤参数）。这是设计也是约束。

## 三条铁律

1. **键必带前缀**：`<prefix>.<语义>`。前缀建议 = 插件 id 去连字符（`pocket-host` → `hostmon.` 也可自定短前缀）。无前缀 = 污染他人 + 被他人污染 + 你自己的清扫逻辑误删别人。
2. **键数要省**：`list` 是全局的，键越多所有插件都变慢。**一键一实体是反模式**——1000 个书签写 1000 个键会把全局 list 拖垮。分块：`bmd.rec.0..N` 每块 200 条数组 + `bmd.idx` 索引。
3. **README 写权威键表**：键空间契约是三方（面板/服务/MCP）协作的唯一依据，样例：

```markdown
## 键空间契约（权威）
<id>.settings        全局设置（面板/MCP 写，服务读）
<id>.meta            服务心跳（服务写）
<id>.cmd.<op>.<nonce> 命令键（面板/MCP 写，服务消费=先删后做）
<id>.rec.<n>         记录分块数组（服务单写者）
```

## 读写细节（全部实测）

- `get` 不存在的键：`{ ok: true, result: {} }`，`value` 字段缺省 → 业务层归一为 `null`。
- **所有 get 都包 `.catch(() => null)`**——读到的 key 可能刚被并发删掉。
- `set` 的 value 直接是 JSON 对象（宿主序列化），单值建议 ≤256KB（分块阈值按此估）。
- 没有 TTL、没有 CAS、没有批量接口。TTL 语义自己做（值里存 `expiresAt`，读时判）。

## 清扫与防误伤

- 自己前缀的键才可删。批量删除前再 filter 一次前缀（`keys.filter(k => k.startsWith(PREFIX))`），冒烟脚本清场同规则。
- 冒烟护栏：**真实环境 kv 里已有本插件业务键时拒跑**（如 `bmd.rec.*` 存在即中止），防冒烟毁生产数据（memoryforge 先例）。测试数据用独立子前缀（`<prefix>.smoke.*`）并 100% 清理。
