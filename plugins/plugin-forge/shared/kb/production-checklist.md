# 生产级清单（data-ark 标准）

「演示能跑」和「生产级」的差距就是这张清单。data-ark（备份引擎）确立的标准，后续插件照此验收。

## 数据安全

- [ ] **原子写**：先写 `.tmp` 再 `fs.renameSync`，索引/manifest 最后写——崩溃后要么完整要么没有
- [ ] **单写者**：每个键空间一个写者；多方协作走命令键（先删后做）——见 single-writer
- [ ] **幂等**：同 id 重放无副作用；「错过调度只补一次」；重试不双写
- [ ] **清扫护栏**：批量删只动自己前缀；冒烟前检测业务键存在则拒跑
- [ ] **恢复/导出只进暂存区**：引擎没有直接覆盖用户数据的代码路径（data-ark 恢复只写 restored/）

## 网络安全

- [ ] **SSRF 守卫**：服务抓取只放公网 http(s)，拒环回/内网/链路本地/云元数据/file:/javascript:（isFetchableUrl 样板，改动必须保留）
- [ ] 抓取带 UA/Accept、超时必设（AbortController）、响应体限长（读流 reader 循环 + 超限 cancel）
- [ ] 不把敏感数据写日志；kv 里的敏感字段明确标注（README 说明数据出不出设备）

## 可靠性

- [ ] **诚实降级**：bridge 不可达 → 降级跑（健康端点仍 200），meta 标 degraded，60s 刷端点；不自愈失败就明说
- [ ] **日志自落盘 + 轮转**（宿主不收集 stdout）；错误带上下文（哪个 URL/哪个阶段）
- [ ] 服务重启安全：状态全在 kv，进程无记忆依赖；启动扫描能接上中断的工作（≤3 次重试后诚实标记放弃，不堵队列）
- [ ] 限频/告警键**必须含区分维度**（pocket-host 教训：限频键不含 mount，双盘告警互吞）
- [ ] 并发礼貌：外网抓取限并发数（6~8）+ 排队，不轰炸目标

## 交互诚实

- [ ] 失败原因写给人看 + 下一步动作；不做假进度条
- [ ] 危险操作（删库/清空/杀进程）confirm 门（MCP 侧 + 面板侧双确认）
- [ ] 性能边界如实写 README（不采集的指标、不支持的格式，明说）

## 验证闭环

- [ ] shared core 离线单测全绿（行为级，不只 happy path）
- [ ] `tsc --noEmit` + esbuild 构建通过
- [ ] 真实桥冒烟 N/N（含真实外网用例 + 自清理），真实生产数据未被破坏
- [ ] README 键空间契约表 + 权威说明（出错的排查入口：日志路径）

## 分寸（同等重要）

- 拆分克制：能一个文件说清不拆三个；>1800 行再考虑拆
- 不加「以防万一」的兜底分支掩盖设计问题——发现设计缺陷先改设计
- 兜底必须诚实标记（skipped/degraded），不静默吞错
