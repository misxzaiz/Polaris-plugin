# 双语阅读 yizhou —— 网页双语翻译与沉浸阅读

> 把「读外文网页要开翻译、贴给 AI、读完就丢」变成 **一句话入书架，中外交对照，本地跨端随时读**。
> 对 AI 说「帮我把这篇翻译成双语：<链接>」——抓取、抽正文、逐段翻译、存进书架；面板里读，手机上也能读。

选型与市场证据见 `docs/yizhou-plan.md`（沉浸式翻译 3000 万用户、年费 500-700 元吐槽、隐私事件 → 本地化 + 自带模型差异化）。

## 快速开始

1. 插件中心安装「双语阅读」→ 左侧 ActivityBar 出现 🌐 面板（零后台服务，打开即用）。
2. 对 AI 说一句话（MCP 工具自动接管）：

```
帮我把这篇翻译成中英对照：https://example.com/article
```

3. AI 抓取 → 分段 → 逐批翻译（每批一次工具调用）→ 完成后打开「双语阅读」面板阅读。
4. 中途关掉对话也没关系——对 AI 说「继续翻译《标题》」即从断点续译。

## 核心能力

| 能力 | 说明 |
|---|---|
| 对话式入口 | 一句话入书架；AI 经 6 个 MCP 工具完成全部动作，无需填表单 |
| 打分抽取 | 琥珀同款候选容器打分（Readability 思路），导航/侧栏/页脚不进正文 |
| 字符集探测 | BOM → 响应头 → meta 三级探测，GBK/Big5 老页面不乱码 |
| 结构保留 | 标题/列表/引用/代码分段保留标记；**代码段系统自动原样收编**（不浪费 token） |
| 断点续译 | 逐段 upsert 幂等，`yz_more` 缺省自动跳到第一个未译批 |
| 双语阅读器 | 双语/译文/原文三态、字号 A-/A+、阅读进度三端同步（cap.kv） |
| 断点横幅 | 未译完的文章在阅读器顶部给出一键复制的续译指令 |
| 导出 | 阅读器一键复制当前形态 Markdown |
| 跨端 | 手机/Web 打开同一面板读同一书架（数据面 cap.kv，两端放行） |
| 数据所有权 | 全部数据在本地 kv；无账号、无上传、无独立订阅（用你已配置的模型） |

## 与 AI 的对话约定（MCP 工具）

| 工具 | 用途 |
|---|---|
| `yz_fetch` | 抓取+抽取+入库，返回批次 0 原文与翻译契约（段号/标记保留规则） |
| `yz_more` | 取下一批（batch 缺省 = 第一个未译批，即断点续译入口） |
| `yz_save` | 保存一批译文 `items=[{i,dst}]`；幂等可重试，返回进度与下一步 |
| `yz_list` | 书架清单（id/标题/站点/进度）；「继续翻译之前那篇」先查这里 |
| `yz_read` | 读双语/原文/译文全文（供 AI 引用、总结、朗读脚本） |
| `yz_delete` | 删除文章（confirm 门；连同全部译文） |

翻译质量契约写在 `yz_fetch` 的返回里（逐段不合并、标记前缀保留、表格 ` ｜ ` 分隔）；译文随段落存储，进度=`已译段/总段`。

## 架构

```
AI 对话 ──MCP 六工具（stdio JSON-RPC）──────────────────────┐
  yz_fetch：SSRF 守卫 → 原生 fetch(20s/3MB) → 三级字符集探测   │
  → 琥珀同款打分抽取 → markdown-lite 分段 → cap.kv yz.* 入库    │
  yz_save：逐段幂等 upsert（断点续译）                          ▼
                                      cap.kv yz.* 键空间
面板（书架/阅读器）──宿主 invoke → router_dispatch → cap.kv ──┘（只读 art；写 pos/settings/删除）
```

**为什么零服务进程**：抓取只在 MCP 进程（宿主拉起的本地 node，无浏览器同源策略限制）；
面板数据全走宿主通道。相比琥珀/订阅雷达省掉一个常驻服务，故障面与启动开销为零。
代价（如实）：**面板内一键免对话翻译暂不支持**——没有对话就没有 AI 在场；二期可挂调度器。

**复用清单**：`shared/html.js`（DOM 解析）、`shared/extract.js`（打分抽取 + 新增 `extractBlocks`
分段导出）、`shared/charset.js`（字符集探测）、`shared/kvclient.js`（端点自发现桥）均来自
amber 生产实现（文件头注明来源）；MCP 骨架与面板范式对齐 maian/flashforge。

## 键空间契约（权威，三方一致）

| 键 | 写者 | 内容 |
|---|---|---|
| `yz.idx` | **MCP**（登记/存译）+ **面板**（删文重写） | 索引数组 `IdxEntry[]`（新→旧） |
| `yz.art.<id>.p.<c>` | **仅 MCP** | 段落分块（100 段/块）`Seg[]`，`{i,src,dst?,at?}` |
| `yz.pos.<id>` | **仅面板** | 阅读进度 `{segIdx,pct,at}`（MCP 删文时一并清理） |
| `yz.settings` | **仅面板** | `{mode,fontScale}` |
| `yz.smoke.*` | 仅测试 | 冒烟数据（跑完自清） |

`id = articleId(url)`（双 FNV-1a 16 hex，URL 稳定）；同一 URL 重新抓取 = 替换正文并清空旧译文（工具返回会注明）。
`yz.idx` 为双写者（同一用户低并发、读并改写窗口毫秒级），与 maian 面板/MCP 双写成员键同一风险档。
空库时 `yz.idx` 整键删除（卸载即净）。

## 已知边界（如实）

- **JS 动态渲染页抓不到正文**：MCP 进程做的是静态 fetch，SPA 空壳会如实报错并建议「浏览器打开后复制正文让我直接翻译」——不做无头浏览器（体积/复杂度不值，page-sentinel 场景才需要）。
- **翻译消耗你的模型 token**：约为原文 2 倍字符量的进出；单篇上限 12 万字符（超出如实拒绝），批次返回上限 1.2 万字符。
- **重抓同 URL 清空旧译文**：想保留旧版请先复制导出。
- **翻译质量取决于你配置的模型**：插件不做任何翻译降级/兜底；契约里明确要求 AI 保留结构标记。
- **面板一键免对话翻译未做**（二期，挂调度器 prompt 任务）；EPUB/PDF/字幕不在 v1。
- 面板删除走「面板重写 idx + 清 art 块」，与 MCP 写同一键——多开两个 Polaris 同时操作同一书架的理论竞态存在（与全生态 cap.kv 无 CAS 的前提一致），单人使用可忽略。

## 安全设计

- SSRF 守卫（amber/feed-radar/clip-relay 同源）：拒绝内网/环回/链路本地/云元数据地址，仅公网 http(s)。
- 抓取上限 3MB / 20s 超时；正文上限 12 万字符；单值键 ≤ 单段大小（远低于 256KB 建议）。
- 面板零外网；MCP 进程是唯一出网点（与全生态抓取型插件同一信任边界）。
- 删除有 confirm 门；冒烟有「书架非空 → 只读」护栏。
