# RELAY 开发者工具箱 — 集成设计方案（规划，非实现）

> 日期：2026-06-06　状态：已批准 · P0–P4 已实施（单文件落地），待端到端验证
> 实施实现说明：注册表以「常驻多视图 + hash 路由 + 懒初始化」落地（`VIEWS`/`TOOLCARDS`
> + `applyRoute()`，每工具首次进入才 `initXxxTool()`）；JSON 工具复用 API 的
> `viewObject/viewTable/viewRaw/collectPaths/richValue/getByPath`，通过给状态对象挂
> `rerender` 钩子复用多表格切换（API 不挂钩 → 行为不变）。
> 背景：把单一的 API 请求工具升级为「开发者工具箱」，加首页（工具卡），并集成
> JSON 工具、SQL 模板填充、时间戳转换等。参考来源：`invoke` 仓库的
> `json-view.html`（JSON→表格渲染器）与 `sql-build.html`（SQL 模板执行器）。

---

## 0. 一句话推荐
**单文件 SPA + 工具注册表（tool registry）+ hash 路由 + 共享核心**。
保留项目「零构建、零依赖、一个 `index.html` + 小 `server.py`」的基因；共享核心只写一份、
所有工具复用（杜绝多页面方案的“复制即漂移”）；新增工具 = 注册一个描述符，O(1) 扩展；
并保留向 ES 模块演进的干净接缝。

## 1. 为什么是它（长期视角）
| 维度 | 单文件+注册表（选） | 多页面 /tool/*.html | ES 模块多文件 |
|---|---|---|---|
| 代码重复/漂移 | 无（核心共享一份） | 严重（设计系统+渲染器各页复制） | 无 |
| 新增工具成本 | 低（注册描述符） | 中（整页+复制样式） | 低（加文件+注册） |
| 构建/依赖 | 零 | 零 | 零（原生 import） |
| 可移植/部署/分享 | 最强（单文件） | 中 | 中（需 http 加载模块） |
| 从现状迁移风险 | 低（现有逻辑包成首个工具模块） | 中 | 高（全局闭包→导入导出大改） |
| 超大规模/多人协作 | 够用（靠约定） | 差 | 最佳（文件级隔离） |

**结论**：以本项目规模（数个开发小工具）与基因，单文件+注册表 ROI 最高、风险最低，
又能拿到长期最关键的“无重复、易扩展”。**仅当**预期增长到 10+ 工具或多人长期并行开发，
才值得切到 ES 模块——而注册表 + 每工具 `mount()` 与模块是 1:1 映射，届时迁移是机械工作。
故现在不做模块化（YAGNI），但**留好接缝**。

## 2. 单文件内部结构
```
index.html
├─ CORE/tokens     设计变量（现有 obsidian + signal-coral，不变）
├─ CORE/util       $, $$, esc, el, copy, toast, store(命名空间持久化)
├─ CORE/json-view  collectPaths / getByPath / richValue / viewTable+列宽 /
│                  jsonNode+对象树 / 路径下拉 / 悬停浮层 / 原始高亮
│                  （从 API 工具里抽出，泛化为 (container, data, opts)，工具无关）
├─ CORE/http       send + /__proxy 路由（现有）
├─ ROUTER          hashchange：unmount 旧 → mount 新；默认 #/ = 首页
├─ HOME            工具卡launcher
└─ TOOLS[]         注册表：每个工具一个描述符
```
工具描述符接口（设计示意，非最终代码）：
```js
{ id:'json', name:'JSON 工具', icon:'{}', desc:'格式化·树·表格·路径',
  accent:'var(--m-post)', mount(root){…}, unmount(){…} }
```
- 每工具独占 `#view` 下子树、独立 localStorage 命名空间 `relay.tool.<id>`。
- 顶栏常驻：品牌(回首页) + 工具切换下拉 + 每工具动作槽。
- 路由：`#/`,`#/api`,`#/json`,`#/sql`,`#/time` → 深链、浏览器前进/后退、可分享。

## 3. 阶段计划（每阶段独立可验证、可交付）
- **P0 重构（行为不变）**：把 JSON 渲染与工具函数抽到 CORE；现有 API 客户端整体包成
  `tools/api`。**不改任何现有行为**，复跑现有 31 项 e2e（指向 `#/api`）确保零回归。
- **P1 首页 + 路由**：工具卡 launcher + hash 路由 + 常驻顶栏。
- **P2 JSON 工具**：见 §4。
- **P3 SQL 工具**：见 §5。
- **P4 时间戳工具**：见 §6。
风险集中在 P0（全局闭包重组为 core+registry），用现有 e2e 兜底；P1–P4 为增量新增，风险低。

## 4. JSON 工具（复用现有渲染器 + 吸收源页优点）
- 左：JSON 输入框（粘贴）；动作：格式化 / 压缩 / 校验(报错定位行列) / 转义·去转义 /
  加载示例 / 清空 / 复制。
- 右：复用 API 响应的**同一套**视图——对象树 / 表格（多表格候选·路径下拉·筛选·省略·
  悬停全显·列宽拖拽·图片缩略图·时间戳）/ 原始(高亮)。
- 从源页吸收：**统计卡片**(行/总数/列)、**字段=值 下拉筛选 + 唯一值列表**、
  **点单元格即筛选**(写入筛选并高亮)。路径识别用我们更强的 `collectPaths`。
- 数据流：粘贴文本 → parse → 复用渲染管线；非法 JSON → 行列定位的内联报错。

## 5. SQL 工具（占位符填充 + 日志清洗 + MyBatis 解析）
- 模式①：`带?的SQL ::: [p1, p2, …]` → 按序替换；类型判断（整数/小数/布尔/NULL 不加引号，
  其余加引号并转义单引号）；`?` 数与参数数不匹配时高亮提示；尽力忽略字符串/注释内 `?`。
- 模式②：**MyBatis 日志**——粘贴含 `Preparing: … ?` + `Parameters: a(String), 1(Integer), null`
  的日志，按类型自动配对生成可执行 SQL；保留 `*/ ` 前缀清洗。
- 输出：只读结果 + 复制 + 轻量 SQL 关键字高亮（可选）；防抖实时。
- 重点：**修掉源工具的崩溃点**（参数缺失、`?` 落在字符串里、空串被当数字）。

## 6. 时间戳工具
- 双向：输入 epoch（自动识别 秒/毫秒/微秒）→ 本地 & UTC 的 `YYYY-MM-DD HH:mm:ss`、
  ISO8601、相对时间；输入日期串 → 反推 秒/毫秒 epoch。
- “现在”实时刷新、时区切换（本地/UTC）、各格式一键复制。复用 `fmtDate`。

## 7. 横切关注
- 持久化命名空间隔离；主题/字体不变；状态栏复用；快捷键在各工具语义化（Cmd/Ctrl+Enter）。
- `server.py` **不变**（仍 静态 + `/__proxy`）。
- 验证：扩展 `relay-verify.js` → 路由(首页↔各工具)、JSON 粘贴渲染、SQL 两模式、
  时间戳双向、API 回归 31 项。

## 8. 暂不做（留作未来）
- 构建/打包、ES 模块拆分（作为增长后的 escape hatch）。
- “更多小工具”（Base64 / URL 编码 / UUID / 文本 Diff）——按注册表后续逐个加。
- SQL 可视化 SELECT 构建器（源文件无此功能、工作量大）。
