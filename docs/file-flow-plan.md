## 二、需求证据

**痛点**：下载文件夹无序是普遍高频痛点；「Hazel for Windows」是长期反复出现的需求问句。
- Reddit r/software「Developing a program for automatic file management」：File Juggler 开发者自述因在 Windows 找不到 Hazel 等价物而创业（https://www.reddit.com/r/software/comments/xrsco/）。
- 2025-2026 年出现多款商业新产品（Filect、Sortio、File Arbor）自我营销为「Hazel for Windows」——有厂商为此付费赛道下注，需求真实性交叉印证（https://filect.io/blog/hazel-alternative-for-windows 、https://zushapp.com/blog/hazel-for-windows-alternatives）。

**现有方案缺口**（Windows 免费/本地/中文场景）：
- DropIt：免费但开发停滞（末版 2017 年前后）、拖拽范式老旧、无预览式 dry-run、无撤销。
- File Juggler：收费（$40 档）。
- Power Automate Desktop：重量级、学习成本高、非为「文件夹收拾」设计。
- PowerShell/AHK 自写脚本：每个用户重复造轮子，无预览、无撤销、无跨端查看。

**插件形态优势**：
1. 后台常驻服务样板成熟（net-sentinel/time-trail 先例），原生 fs 监听零跨域。
2. 面板经宿主 invoke→cap.kv，桌面/手机/Web 三端天然同源——手机上也能看「整理了什么」。
3. MCP 工具让 AI 一句话生成规则、执行整理、回答「下载文件夹怎么样了」——现有独立软件均无对话式规则生成。
4. dry-run 先行 + 批次撤销日志，解决「不敢让程序动我的文件」这一现有工具的最大信任缺口。

## 三、MVP 范围

**做**：多根目录；规则引擎（扩展名/名称正则/大小/年龄/子目录匹配 + move/recycle/dedupe/rename 动作 + 目标模板 `{yyyy}-{mm}` 变量）；dry-run→apply（批次日志）→按批撤销；fs.watch 常驻监听（新文件年龄护栏 ≥guardMinutes、部分下载后缀排除）；预置「下载夹起步包」；面板四页（总览/规则/历史/设置）；MCP 七工具。

**不做**（明确边界）：按内容 AI 分类、真实系统回收站 API、永久删除（回收=移入 `<root>/_FileFlow回收站/`）、跨设备文件同步、非本机路径。

**成功指标**：目标——500 文件根目录 dry-run < 3s；撤销 100% 逐文件可还原；护栏（正在写入/占用文件）零误动。实测值见交付报告。

## 四、关键设计决策

1. **一切数据走 cap.kv 单写者**（键空间 `fileflow.*`）：面板/MCP 只读快照+写命令键，服务 tick 消费（先删后做）——复用 disk-radar/net-sentinel 已验证协议，天然三端一致。
2. **安全模型**：动作仅 move/rename（同盘 rename，跨盘 copy+verify+unlink）；永不删除；目标目录默认限根内，根外需规则显式 `allowOutsideRoot` 且首次 apply 前强制 dry-run；EBUSY/EPERM（文件被占用）跳过并如实记录；新文件护栏防「正在写入的文件被搬走」。
3. **undo 语义**：批次日志记录 from→to；撤销时逐文件校验「to 仍在、from 已空」才回移，冲突/失败如实报告，不做魔法。
4. **规则目的目录自动排除**：启用规则的目标子树不参与匹配，防「冷存规则把归档又搬走」的递归搬家。

## 五、最大不确定性与止损

- 不确定性：用户是否信任自动搬运 → 以 dry-run 默认 + 撤销日志 + 自动模式默认只处理「新到文件」（历史文件仅手动整理）降险。
- 止损：若 Windows 文件监听在真宿主不稳定（锁/权限噪声），降级为纯手动「立即整理」模式，产品价值仍成立。
